# Codebook

Companion reference to `README.md`: the domain model, the on-disk file
format, validation rules, and the testing notes for Task 3
(DLBMINPAPCC01_E), Smart Inventory Management System.

## Entities

**Product**: `sku` (string, primary key, format `PRD-<millisecond
timestamp>`, auto-generated by the GUI and regenerable), `name`,
`category`, `unitPrice` (double, must be >= 0), `quantityOnHand` (int,
must be >= 0), `reorderThreshold` (int, must be >= 0), `supplierId`
(string, must reference an existing `Supplier`), `imagePath` (string,
optional, GUI-only).

**Supplier**: `id` (string, primary key, format `SUP-<4-digit sequence>`,
auto-generated by the GUI and regenerable), `name`, `contact`.

**Transaction**: `id`, `timestamp`, `productSku` (must reference an
existing `Product`), `type` (`StockIn`, `StockOut`, or `Adjustment`),
`delta` (int), `note`.

## Memory model

`Inventory` owns every `Product`, `Supplier`, and `Transaction` by value in
its own `std::vector`, with an `std::unordered_map<sku, index>` (and the
supplier/transaction equivalents) for O(1) lookup. Cross-entity references
(`Product::supplierId`, `Transaction::productSku`) are plain string IDs
rather than pointers or iterators, so they stay valid across vector
reallocation.

## File format

`products.dat`, `suppliers.dat`, and `transactions.dat` are a custom
escaped CSV-like format, one record per line, fields separated by commas,
with quoting/escaping for embedded commas and quotes. `Persistence` saves
after every mutating call and rebuilds the in-memory vectors and indexes on
load; a missing file is treated as an empty collection, and a malformed
line is skipped with a warning rather than aborting the load. Since the
finalization pass, a save writes to a `<file>.tmp` file first and only then
renames it over the real file (`std::rename`, a single atomic filesystem
operation on the platforms this targets), so a crash or power loss mid-save
leaves the previous, intact file in place instead of a half-written one.

## Validation rules (enforced by `Inventory`, exercised by the test suite and the GUI)

- A product SKU must be non-empty and unique; adding a duplicate SKU is
  rejected.
- A product's `supplierId` must reference an existing supplier.
- Numeric fields (`unitPrice`, `quantityOnHand`, `reorderThreshold`) must
  parse as non-negative numbers; invalid input is caught and reported as a
  status message rather than crashing either interface. Since the
  finalization pass, `unitPrice` is also checked with `std::isfinite`, so a
  value that parses as `inf` or `nan` (which would otherwise pass a plain
  `>= 0` comparison) is rejected the same way a negative price is.
- A stock-out movement that would drop `quantityOnHand` below zero is
  rejected.
- A supplier cannot be removed while any product still references it
  (`supplierId` match) — enforced in `Inventory`, not just checked in the
  UI. Confirmed live: attempting to remove a referenced supplier returns
  "Error: supplier SUP-0001 is still referenced by a product" and the
  supplier is not removed.

## Testing

`inventory_tests` (37/37 checks passing) covers input validation,
duplicate/unknown-SKU and unknown-supplier rejection, stock movements
including the below-zero guard, search, sort, and a save/reload
persistence round trip exercising the comma/quote escaping above.

Beyond the automated suite, the GUI was exercised live end to end on the
built `inventory_gui` binary (see `docs/screenshots/`): adding a product
with an image, editing it, removing it, adding a supplier, recording a
stock-out movement and confirming the quantity update and transaction
history, and confirming the supplier-removal referential-integrity check.

### Bugs found and fixed during GUI testing

Both were ImGui widget-ID collisions, not logic errors in `Inventory`
itself:

1. **Add product / Add supplier buttons did nothing.**
   `ImGui::CollapsingHeader("Add product", ...)` and
   `ImGui::Button("Add product")` resolved to the same internal widget ID
   (identical unqualified label), so the button never registered a click.
   Fixed by giving the buttons unique IDs (`"Add product##submit"`,
   `"Add supplier##submit"`) without changing the visible label.
2. **Edit / Remove buttons were visible but did nothing.**
   `ImGui::OpenPopup(...)` was called from inside the per-row
   `ImGui::PushID(sku)` scope, while the matching
   `ImGui::BeginPopupModal(...)` is outside that scope, so the popup ID
   never matched and the modal could never open. Fixed with the standard
   ImGui pattern: set a boolean flag inside the `PushID` scope on click,
   then call `ImGui::OpenPopup(...)` at the correct, unscoped ID level
   immediately before each `BeginPopupModal`.
